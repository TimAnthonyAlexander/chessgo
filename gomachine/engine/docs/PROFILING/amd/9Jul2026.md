# Engine CPU profile — 9 Jul 2026 (amd64 / coalla, AVX-512 GOAMD64=v4)

**This is the current main profile.** See `7Jul2026.md` for the previous baseline
(mirror-KB net `mirror_kbhm_320`, pre-efs28, pre-margin-retune) and `6Jul2026.md`
for the one before that.

Prod-representative SIMD build (`GOEXPERIMENT=simd GOAMD64=v4 go1.26.4`), **efs28
data-pipeline net** `data/nnue/kb-mirror.bin` (44 MB, H=512 NB=8, 16 king-buckets
with horizontal mirror, 32-key Finny refresh cache; md5 `92294de3…`). Commit
`4266d25` (coalla built at `62c2214` — the delta is a docs-only commit, so the
engine binary is identical). All §30.2 perf wins present in the config sweep:
`SetFinny(true)`, `SetSplitRefresh(true)`, `SetDirectApply(true)`, 512-bit
`screluDot` widen, PEXT sliders, qsearch SEE dedup. Profiler: Linux `perf record
-F 999 --call-graph fp`, then `perf report --no-children` for flat (Self)
percentages. **Whole-process profile of the full `bench nps` config sweep** (all
7 accumulator-push configs interleaved, same as 7 Jul), **not** `-baseonly`.

## Changes since 7 Jul

- **Net: mirror KB → efs28 (`chessgo_efs28_wdl06_640`, md5 `92294de3…`).** Same
  arch (H512 NB8 KB-mirror) — the NNUE **code is byte-identical** (`git diff
  0dfa6f3..HEAD -- internal/nnue/` is empty), only the trained weights changed.
  Retrained on the FIXED data pipeline (early-fen-skipping `ply≥16→28` = SF's
  master-net cutoff, superbatches `320→640`, `ConstantWDL 0.6`): **+18.8 Elo @
  100ms** over the prod mirror net (§32). Because the arch/code is unchanged, the
  **eval kernel shape is unchanged** — efs28 is an eval-*quality* win, not a
  speed change.
- **Shipped search-margin re-tune** (now in `search.DefaultParams()`):
  `NullMoveR 4→3`, `CaptSEEMaxDepth 6→4`, `SingularDepth 8→6`,
  `SEEQuietMargin 150→75` (the 75 is the 2026-07-08 mirror-KB SPSA snapshot
  k≈353, adopted as the new base; the 2026-07-05 bundle was +38.7 ± 5.5 Elo @
  movetime, 640 pairs). **This is a search-behaviour change** — it reshapes the
  tree, which is the dominant delta in this profile (see below).

**Net effect on the profile:** NPS is essentially flat vs 7 Jul (identical eval
arch, byte-identical kernels — prod(base) 537k vs ~534k). What moved is the
**node count at fixed depth** and the **search-vs-eval split**: the margin retune
+ efs28's different move ordering push more work into `negamax`/`selectMove` and
change the tree. **Depth-16 node count rose 958,899 → 1,457,971/iter (+52%);
depth-14 rose 245,723 → 561,200/iter (+128%)** — the clearest signature of the
retune (singular extends deeper at `SingularDepth 6`, `NullMoveR 3` reduces
differently) plus efs28's altered cutoffs. This run also captured **~10× more
perf samples** (268k vs 26.7k eval), so low-level kernels are far better resolved.

**Key differences from 7 Jul:**
- **`negamax` is now the #1 flat cost (11.57%, up from 8.92%)** and `selectMove`
  is #3 (8.34%). Combined with the +52% node count at fixed depth, this is the
  margin retune's fingerprint: `SingularDepth 6` extends deeper and the tree
  reshapes, so proportionally more time is α-β/ordering, less is raw eval.
- **`addColI8SIMD` fell 11.83% → 9.44%** and **`screluDotSIMD` 11.20% → 5.23%.**
  Part is the search-vs-eval reweighting above; part is that 7 Jul had only
  26,677 samples, so those two large numbers were high-variance. This run's
  268k samples give a more stable, lower forward-pass share.
- **`applyThreatBatchSIMD` appears (5.42%)** where 7 Jul didn't list it. It is
  **byte-identical** code (zero nnue commits since 7 Jul) exercised only by the
  `batchApply`/`batch+pf` sweep configs (2 of 7). On amd64 those configs are a
  *loss* (ratio ≈ 0.99) — batchApply is an ARM win, an amd64 wash (see
  `perf-ideas-7jul2026.md` §1) — so this is a **bench-aggregate artifact, not a
  prod hot spot**; the prod `finny` config (ratio 1.068) never calls it.
- `buildAccHalf` stays collapsed at 0.55% flat (splitRefresh + Finny), same as
  7 Jul — the §30.2 headline win holds.
