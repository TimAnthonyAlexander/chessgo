# Engine CPU profile — 7 Jul 2026 (amd64 / coalla, AVX-512 GOAMD64=v4)

**This is the current main profile.** See `6Jul2026.md` for the previous baseline
(pre-mirror KB net, pre-§30 perf wins, pre-Finny).

Prod-representative SIMD build (`GOEXPERIMENT=simd GOAMD64=v4 go1.26.4`), mirror
KB net `data/nnue/kb-mirror.bin` (44 MB, H=512 NB=8, 16 king-buckets with
horizontal mirror, 32-key Finny refresh cache). Commit `0dfa6f3` (HEAD, clean).
All §30.2 perf wins active: `SetFinny(true)`, `SetSplitRefresh(true)`,
`SetDirectApply(true)`, 512-bit `screluDot` widen, PEXT sliders, qsearch SEE
dedup. Profiler: Linux `perf record -F 999 --call-graph fp`, then `perf report
--no-children` for flat (Self) percentages.

## Changes since 6 Jul

- **Net:** factorized KB → mirror KB (horizontal king-bucket mirror, §31).
  Better eval quality per node (~+10 Elo at movetime); denser training data per
  bucket for ~0 extra params.
- **32-key Finny refresh cache** (`SetFinny(true)`, bit-exact +2.3% NPS over
  splitRefresh, confirmed 3 interleaved reps on 7 Jul). The old profile used no
  Finny cache at all — bucket-crossing king moves did a full dual rebuild.
- **splitRefresh** (only the moving side's half rebuilt on bucket change,
  §30.2, +2.3% NPS). Not in the old profile.
- **directApply** (skip counts-array multiset diff, §30.2, +2.5% NPS). Not in
  the old profile.
- **512-bit screluDot widen** (§30.2, +2.0% NPS). Old profile used 256-bit.
- **PEXT slider attacks** (§30.2, +2.4% NPS). Old profile used magic
  multiply-shift.
- **qsearch SEE dedup** (§30.2, +2.8% NPS). Not in the old profile.
- **screluDot 256→512 widen** old profile already had this? No — the old
  profile's `screluDotSIMD` was still 256-bit (the widen landed in `54d0271`).

**Net effect on NPS: mirror's d/e-crossing king-move rebuilds cost ~7% at fixed
depth on amd64, partially offset by the §30.2 perf wins. The +10 Elo is eval
quality (denser training data), not speed — confirmed by §31.3 SPRT (+4.74 Elo
at movetime, 32-key Finny).**

**Key differences from 6 Jul:**
- `buildAccHalf` collapsed from 15.2% cum to 0.76% flat — the single biggest
  change. splitRefresh (moving-side-only rebuild) + Finny (refresh cache on
  bucket revisit) together killed the full king-bucket refresh cost. This is
  the §30.2 perf push's headline win.
- `screluDotSIMD` grew 6.0% → 11.2% flat — the 512-bit widen made the kernel
  faster (+2.0% NPS), but accumulator maintenance shrank more (splitRefresh +
  directApply + Finny ≈ +7%), so the forward pass takes a proportionally larger
  share. Perf counter confirms: it's faster in absolute cycles, just bigger
  relative to a cheaper accumulator.
- The `archsimd` Load/Store inlines (`LoadInt16x32Slice` 3.2%,
  `Int16x32.StoreSlice` 3.4%) disappeared — consolidated into the 512-bit
  `screluDotSIMD`.
- **Search functions surfaced in the eval profile:** `negamax` (8.9%),
  `selectMove` (8.1%), `scoreMoves` (3.5%) are now first-class costs at depth
  16. The old eval profile was eval-dominated enough that these didn't register.
- `pext.abi0` at 0.90% is the PEXT slider-attack stub — the magic→PEXT switch
  is visible but small (the +2.4% NPS win is spread across callers).
