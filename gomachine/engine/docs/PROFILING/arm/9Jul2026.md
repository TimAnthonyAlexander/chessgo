# Engine CPU profile — 9 Jul 2026 (arm64 / M3, NEON)

**This is the current main profile.** See `7Jul2026.md` for the previous baseline
(mirror-KB net `mirror_kbhm_320`, pre-efs28, pre-margin-retune) and `6Jul2026.md`
for the one before that.

SIMD arm64/NEON build (`GOEXPERIMENT=simd go1.27rc1`), **efs28 data-pipeline net**
`data/nnue/kb-mirror.bin` (44 MB, H=512 NB=8, 16 king-buckets with horizontal
mirror, 32-key Finny refresh cache; md5 `92294de3…`). Local commit `4266d25`.
All §30.2 perf wins present in the config sweep: `SetFinny(true)`,
`SetSplitRefresh(true)`, `SetDirectApply(true)`, 256-bit `screluDot` widen,
qsearch SEE dedup. PEXT is **amd64-only** — M3 stays on magic bitboards.
Profiler: Go `runtime/pprof` (`--cpuprofile` on `bench nps`); `go tool pprof
-top`. Whole measured section of the full `bench nps` config sweep (all 7
accumulator-push configs interleaved), one depth per invocation.

## Changes since 7 Jul

- **Net: mirror KB → efs28 (`chessgo_efs28_wdl06_640`, md5 `92294de3…`).** Same
  arch (H512 NB8 KB-mirror) — the NNUE **code is byte-identical**, only the
  trained weights changed. FIXED data pipeline (early-fen `ply≥16→28`,
  superbatches `320→640`, `ConstantWDL 0.6`): **+18.8 Elo @ 100ms** over the prod
  mirror net (§32). An eval-*quality* win, **not** a speed change — the NEON
  kernel shape is unchanged.
- **Shipped search-margin re-tune** (now in `search.DefaultParams()`):
  `NullMoveR 4→3`, `CaptSEEMaxDepth 6→4`, `SingularDepth 8→6`,
  `SEEQuietMargin 150→75`. A **search-behaviour change** that reshapes the tree —
  the dominant delta here.
- **NPS band unchanged** (~479k prod(base), same as 7 Jul's ~482–491k). What
  moved is the **node count at fixed depth** (depth-16 958,899 → 1,457,971/iter,
  +52%; depth-14 245,723 → 561,200/iter, +128%) from the retune + efs28's altered
  move ordering. This run also captured a much longer profile (246s eval vs the
  old ~24s), so archsimd Load/Store inlines are cleanly resolved.

**Key differences from 7 Jul:**
- `addColI8SIMD` dropped 18.99% → 15.86% and `subColI8SIMD` 10.00% → 8.04% —
  the eval-vs-search reweighting from the margin retune (more α-β per leaf), not
  a kernel change (nnue code is byte-identical).
- `negamax` rose 2.71% → 3.30% and node count at depth 16 rose +52% — the
  retune's tree reshape, same signature as amd64.
- **`applyThreatBatchSIMD` surfaced (6.15%).** Byte-identical code; fires only in
  the `batchApply`/`batch+pf` sweep configs. On ARM those are a genuine **win**
  (ratio 1.029) — narrow 128-bit NEON makes per-column load/store the bottleneck,
  which the batched apply attacks (`perf-ideas-7jul2026.md` §1). Still, the prod
  `finny` config doesn't call it, so it's a sweep-aggregate line, not a prod cost.
- `LoadInt16x8` up 3.90% → 5.83%: as before, the narrow vector units mean
  load/store overhead surfaces as the core kernels stabilize.
- `applyDelta` at 39.34% cum remains the dominant move-aware push path.

- NPS config sweep (eval / search prod(base)→finny): prod(base) 479k/479k,
  splitRefresh 533k/538k, **finny 574k/586k** (the prod path, ~+20% over base —
  the ARM maintenance-bound win, larger than amd64's ~+8%). batchApply 1.029 (an
  ARM win, unlike amd64).
