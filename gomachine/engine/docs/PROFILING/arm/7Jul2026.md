# Engine CPU profile — 7 Jul 2026 (arm64 / M3, NEON)

**This is the current main profile.** See `6Jul2026.md` for the previous baseline
(pre-mirror KB net, pre-§30 perf wins, pre-Finny).

SIMD arm64/NEON build (`GOEXPERIMENT=simd go1.27rc1`), mirror KB net
`data/nnue/kb-mirror.bin` (44 MB, H=512 NB=8, 16 king-buckets with horizontal
mirror, 32-key Finny refresh cache). Commit `0dfa6f3` (HEAD, clean). All §30.2
perf wins active: `SetFinny(true)`, `SetSplitRefresh(true)`,
`SetDirectApply(true)`, 512-bit `screluDot` widen, qsearch SEE dedup. PEXT is
**amd64-only** — M3 stays on magic bitboards. Profiler: Go `runtime/pprof`
(`--cpuprofile` flag on `bench nps`); `go tool pprof -top`. Both eval and
search profiles captured in a single run per depth.

## Changes since 6 Jul

- **Net:** factorized KB → mirror KB (horizontal king-bucket mirror, §31).
  Better eval quality per node (~+10 Elo at movetime).
- **32-key Finny refresh cache, splitRefresh, directApply** — same as amd64.
- **512-bit screluDot widen** — NEON path was widened from 128-bit to 256-bit.
- **qsearch SEE dedup** — same as amd64.
- **NPS up ~5%:** depth 14 went from ~460k → 482k. The mirror net's
  d/e-crossing rebuild cost is lower on ARM (narrower vector units mean
  maintenance is already the bottleneck; the perf wins proportionally help
  more). PEXT doesn't apply so there's no offsetting loss.

**Key differences from 6 Jul:**
- `addColI8SIMD` dropped 20.1% → 19.0% — splitRefresh/Finny reduced the total
  number of full-rebuild columns, and the mirror net's d/e-crossing rebuilds
  are less frequent with the 32-key Finny cache.
- `applyDiff.func1` dropped 4.4% → 2.5% — directApply skips the counts-array
  multiset diff.
- `evalFromHalvesLean` cum dropped 9.5% → 9.0% — small, but the 512-bit
  screluDot widen helps the forward pass.
- `screluDotSIMD` flat dropped 7.8% → 6.5% — the 512-bit widen made it faster
  per invocation.
- `buildAccHalf` (full king-bucket refresh) dropped from 25.4% cum to ~5.8%
  cum — splitRefresh + Finny killed the full dual rebuild on bucket-crossing
  king moves. This is the big win, same as amd64.
- `atomic.Uint64.Load` (TT probe) dropped 3.98% → 1.19% — likely the bench
  overhead artifact shifting (different warmup/iters); not a real TT change.
- `LoadInt8x16` up 3.2% → 6.0% — the narrower vector units mean more
  load/store overhead surfaces when the core kernel gets faster.
