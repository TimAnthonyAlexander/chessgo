# zugzwang CPU profile — 20 Jul 2026 (amd64 / coalla, AVX512-VNNI)

**This is the authoritative profile.** Prod is amd64 (coalla, lairner); the M3 dev box
profiles very differently (see `../arm/20Jul2026.md`) and is only a coarse cross-check.

- **Build:** `g++ -std=c++17 -O3 -flto -DNDEBUG -march=native -ffp-contract=off
  -fno-omit-frame-pointer -pthread` at commit `93e4f56` (LAZYACC default-on).
- **Net:** `net.nnue` → `ft_final.bin` (~189 MB float32 full-threats: H=512, D2=16, D3=32,
  NB=8, 16 king-buckets + horizontal mirror, 79,856 SF full-threats, **int16 threat FT**,
  int8 tail L1, pairwise 16→32).
- **Workload:** 5 positions (startpos, two middlegames, a castling middlegame, a KP endgame)
  driven over UCI, `go depth 18`/`24`. Tool: Linux `perf record -g` → `perf report --stdio
  --no-children` (flat self-time).
- **Two runs:** `LAZYACC=1` (the shipped default) and `LAZYACC=0` (the eager fallback) from
  the SAME binary — byte-identical search (identical node counts), so the only difference is
  which accumulator updates get skipped.

## Headline

- **LAZYACC shipped this session: +7.2% NPS amd64** (573.6k → 615.0k mean, interleaved
  ±3% noise floor) and **+16.3 ± 11.8 Elo movetime SPRT @ 1000 games** (0.1s/move). Byte-
  identical. See `../../` commit `93e4f56`.
- The NNUE accumulator machinery dominates node time: **apply_diff + changed_edges_delta +
  eval_from_halves + (build_half) ≈ 50–58%** of self-time. Search overhead (negamax,
  movepick, movegen, TT) is the rest.

### What LAZYACC changed
Both runs execute the identical search (same nodes). `build_half` (5.80% → <0.8%) is the
visible win: eager rebuilt the accumulator from scratch on *every* king-bucket cross, including
the ~26–88% of do_moves whose child is TT/terminal/beta-cut before any eval reads it; lazy
defers that to `materialize()`, which only runs for slots an eval actually needs. `apply_diff`
stays ~dominant because it still runs on every eval'd path — but on a *smaller* total wall-time
(hence the same ~27% share of a smaller pie ⇒ +7% NPS). `apply_diff` and `changed_edges_delta`
also each run somewhat less in absolute terms for the same reason.

## Lever map (what to attack next, by cost)

1. **`apply_diff` 26.9% — the prize.** Bandwidth-bound on int16 threat columns. The retrain-free
   attack (LAZYACC) is shipped. The remaining big lever is **int8 threat FT via QAT** (halve the
   column bytes → ~2× the streamed bandwidth of the dominant cost). Histogram (this session):
   99.5% of threat weights already fit int8; a *lossy* post-hoc clamp costs 13 cp eval error, so
   it needs quantization-aware **retraining** (August), not a post-hoc transform. Est. ~+4–8 Elo
   on top of LAZYACC.
2. **`changed_edges_delta` 13.2% — LAZYACC v2.** Currently computed EAGERLY at push time (boards
   must be live). Deferring the *enumeration* too (store per-ply board snapshots; recompute the
   delta lazily) would skip it for wasted nodes as well — but needs `active_features` /
   `changed_edges_delta` templatized on a BoardLike type (Position | BoardSnapshot). Another
   few % NPS; a real refactor.
3. **`eval_from_halves` 10.0%** — pairwise activation + int8 dot + tail. Micro-opts here
   (DOTSPLIT / PAIRSIMD / ROUNDFAST) were all measured **sub-noise or negative** this session —
   the kernels are already well-optimized (compiler auto-vectorizes; VNNI dot). Do not re-try
   without a bigger structural change.
4. Search overhead (negamax / score_moves / movegen / TT ≈ 15%) — the search campaign's turf,
   not NNUE.
