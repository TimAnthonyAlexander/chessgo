# zugzwang CPU profile — 20 Jul 2026 (arm64 / M3, NEON)

**Coarse cross-check only — trust `../amd/20Jul2026.md` for decisions.** M3 is a dev box;
prod is amd64. The two arches profile very differently (different SIMD, different inlining),
and the tooling here is weaker.

- **Build:** `g++ -std=c++17 -O3 -flto -DNDEBUG -mcpu=native -ffp-contract=off
  -fno-omit-frame-pointer -pthread` at `93e4f56` (LAZYACC default-on), NEON path.
- **Net:** local `net.nnue` → `kb-mirror.bin` (~189 MB, same full-threats net as coalla's
  `ft_final.bin`).
- **Tool:** macOS `sample <pid> 22` over a 4-position `go movetime 6000` batch, then a
  call-tree → self-time parser (`/tmp/parse2.py` in this session's scratch).

## ⚠️ Methodology caveat (why the numbers are coarse)

macOS has no `perf`. `sample` is a 1 ms **call-tree** sampler, and with zugzwang's aggressive
`-O3 -flto` inlining, most leaf work is attributed to the recursive `negamax` frame rather than
to the inlined callee (movepick, pruning, eval plumbing all fold into `negamax`). So the flat
self-time below is **not reliable** — `negamax` is massively over-counted vs the amd perf
profile (48% here vs 6.4% on amd). Use it only to confirm the same functions dominate, not for
their magnitudes.

## Flat self-time (sample-derived, idle main-thread excluded — COARSE)

| % self (unreliable) | Function |
|---|---|
| 48.0 | `Search::negamax` (⚠ absorbs most inlined callees on arm — see caveat) |
| **15.0** | `NNUE::AccStack::apply_diff` |
| 10.1 | `Search::qsearch` |
| 8.8 | `Eval::evaluate` |
| 5.5 | `Search::start` |
| 3.5 | `NNUE::eval_from_halves` |
| 2.7 | `Position::do_move` |
| 1.8 | `NNUE::changed_edges_delta` |

## What it does confirm

- **`apply_diff` is the top NNUE cost on arm too** (~15% even with negamax over-counting),
  consistent with amd's 26.9%. The NNUE accumulator is the bottleneck on both arches.
- LAZYACC measured **~+6% NPS locally** (arm64: ~577k eager → ~612k lazy on startpos d20,
  byte-identical node counts) — the arm64 gain transferred to +7.2% on amd64.

## arm vs amd

Per the gomachine profiling history, arm64/NEON and amd64/AVX512 diverge (e.g. the int8 dot
has no NEON VNNI, so int16 paths behave differently; inlining differs). **Movetime/Elo
decisions are made on coalla (amd64).** This arm profile exists only to sanity-check that the
same hot functions dominate — which they do.

> For a precise arm flat profile, use Instruments `Time Profiler` (`xcrun xctrace record
> --template 'Time Profiler'`) rather than `sample` — not done here (coarse cross-check was
> sufficient).
